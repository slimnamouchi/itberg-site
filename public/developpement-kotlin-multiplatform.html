Mobile · Kotlin Multiplatform

Développement d’applications en Kotlin Multiplatform

Une application Android et iOS sans payer deux fois le même travail : nous écrivons le code métier une seule fois en Kotlin, et nous partageons l’interface quand c’est utile. Nouveau projet ou migration d’une application Android existante.

Pourquoi Kotlin Multiplatform

Un seul code métier

Les règles, le calcul, la synchronisation et l’accès aux données sont écrits et testés une fois, pour Android et iOS.

Des performances natives

Le code est compilé pour chaque plateforme. Pas de couche d’interprétation entre votre application et le téléphone.

Une adoption progressive

On peut partager un seul module au départ, puis davantage. Rien n’oblige à tout réécrire.

Notre façon de structurer un projet KMP

  1. Domaine en Kotlin pur

    Le cœur métier ne dépend ni d’Android, ni d’iOS, ni de Firebase : il se teste vite et se réutilise partout.

  2. Données hors connexion d’abord

    Base locale partagée, synchronisation en arrière-plan, écrans utilisables même sans réseau.

  3. Interface Compose Multiplatform

    Écrans partagés là où c’est rentable, natifs là où l’expérience l’exige.

  4. Intégration continue

    Chaque modification compilée et testée pour Android et iOS, avant d’arriver dans l’application.

Questions fréquentes

Qu’est-ce que Kotlin Multiplatform ?

Kotlin Multiplatform (KMP) est une technologie de JetBrains, stable depuis fin 2023, qui permet d’écrire une seule fois le code métier d’une application (règles, données, réseau) et de l’utiliser sur Android, iOS, le web ou un serveur. Compose Multiplatform ajoute la possibilité de partager aussi l’interface.

Quelle différence avec Flutter ou React Native ?

Avec Kotlin Multiplatform, le code partagé est compilé en code natif pour chaque plateforme, et vous choisissez ce que vous partagez : seulement la logique, ou aussi les écrans. On peut garder une interface iOS native là où elle compte. Pour une équipe qui connaît déjà Android et Kotlin, la courbe d’apprentissage est faible.

Peut-on migrer une application Android existante ?

Oui, et c’est un de ses atouts : la migration se fait module par module. On commence par extraire le domaine métier en Kotlin pur, puis les données et le réseau, et l’application Android continue de fonctionner à chaque étape.

Quelle part du code est partagée ?

Cela dépend du projet. Le domaine métier, les données et le réseau se partagent presque entièrement. Pour l’interface, Compose Multiplatform permet d’en partager l’essentiel ; certains écrans ou fonctions propres au système (paiement, capteurs, notifications) restent écrits pour chaque plateforme.
