Mobile app security

What an attacker would see, we see first

We audit Android and iOS apps against OWASP’s public standards, with automated tools and manual testing. You get an understandable report and concrete fixes.

Our services

OWASP MASVS audit

Verification of your app against the MASVS (Mobile Application Security Verification Standard), OWASP’s mobile security standard. We choose the right level with you: L1 (baseline security), L2 (sensitive data: health, finance…) and, if needed, R (resistance to reverse engineering).

Testing per the OWASP MASTG

Checks follow the MASTG (Mobile Application Security Testing Guide): each item is tested in a reproducible, documented way, with evidence.

MobSF analysis

Static and dynamic analysis of your APK, AAB or IPA with MobSF (Mobile Security Framework): permissions, secrets left in the code, network configuration, vulnerable libraries. Each finding is then verified by hand to rule out false positives.

Mobile penetration testing

We put ourselves in an attacker’s shoes: traffic interception, certificate pinning bypass, local storage, authentication, API calls, reverse engineering.

Firebase backend security

Review of Firestore and Storage rules, App Check, keys and access, server functions: an app is only as secure as its backend.

Security in your development pipeline

Automated scans on every release in continuous integration, and security-focused code review.

What we check

The main MASVS areas, explained simply.

  • STORAGEStorage: no sensitive data readable on the phone.
  • CRYPTOCryptography: up-to-date algorithms and well-protected keys.
  • AUTHAuthentication: sessions, tokens and biometrics handled correctly.
  • NETWORKNetwork: encrypted communications and verified certificates.
  • PLATFORMPlatform: permissions, deep links and WebViews under control.
  • CODECode: up-to-date dependencies, validated inputs.
  • RESILIENCEResilience: protection against tampering and analysis of the app.
  • PRIVACYPrivacy: data collection limited to what is needed, and transparent.

How an audit works

  1. Scoping and authorisation

    Scope, target MASVS level, test environments. We only work with the written authorisation of the app owner.

  2. Automated analysis

    MobSF and complementary tools on the app files.

  3. Manual testing

    MASTG checks and penetration testing on risky areas.

  4. Report

    Each vulnerability ranked by severity, with evidence, impact and recommended fix. A summary readable by management.

  5. Debrief and re-test

    We present the results to your teams, then verify that the fixes work.

MASVS, MASTG and MobSF are public, open standards and tools. We use them as a working method: ITBerg is not a certification body and does not issue labels.

AI and agent security

An AI assistant or agent opens new doors to attackers. We test them first, based on the OWASP Top 10 for LLM applications.

  • INJECTIONPrompt injection: booby-trapped text, in a message or a document, that hijacks the AI’s instructions. Try our mini-game.
  • LEAKInformation disclosure: the AI reveals internal data, documents or its instructions.
  • AGENCYExcessive agency: an agent that can do more than necessary (send, pay, delete).
  • RED TEAMRed teaming: we try to derail your AI like a malicious user, then strengthen the guardrails.
